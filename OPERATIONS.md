# GitDocs Operational Runbook

This runbook outlines operational workflows, backup/restore procedures, key rotation, and troubleshooting.

---

## 1. Database Backup & Disaster Recovery (V24)

### Automated Backup (PostgreSQL)
Create an atomic, compressed snapshot of the PostgreSQL database:
```bash
pg_dump -h <db-host> -U gitdocs_user -d gitdocs_db -F c -f "gitdocs_backup_$(date +%Y%m%d_%H%M%S).dump"
```

### Clean Disaster Recovery & Restore
To restore into a fresh database or rollback:
```bash
# 1. Terminate active backend and worker instances
# 2. Drop and recreate schema / restore dump
pg_restore -h <db-host> -U gitdocs_user -d gitdocs_db -c --clean --if-exists backup.dump

# 3. Verify migrations status
npm run db:migrate:status
```

## 2. Token Encryption Key Rotation (V22)

To rotate the server-side storage encryption key without downtime:

1. **Generate New Key**: Generate a new 32-byte (64-character hex) key:
   ```bash
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   ```
2. **Deploy with Dual Key Support**:
   - Set `ENCRYPTION_KEY_PREVIOUS` to the current `ENCRYPTION_KEY`.
   - Set `ENCRYPTION_KEY` to the new key.
   - Set `ENCRYPTION_KEY_VERSION="v2"`.
3. **Transparent Reads**:
   The `crypto.service.ts` decrypts existing records using the previous key while writing all new logins using the new key.
4. **Remove Previous Key**: Once older credentials have cycled or been re-encrypted, remove `ENCRYPTION_KEY_PREVIOUS`.

## 3. Webhook Troubleshooting & Reconciliation

- **401 Unauthorized**: Missing or mismatched `x-hub-signature-256`. Check `GITHUB_WEBHOOK_SECRET`.
- **409 Conflict**: Payload digest mismatch for known `x-github-delivery` (tampering detected).
- **200 Duplicate Acknowledged**: Webhook delivered multiple times by GitHub; processed idempotently without extra runs (V11).
- **Self-Generated Commits**: Commits generated by approved documentation proposals are recognized via `CommitIntent` and skipped automatically, preventing infinite loops (V20).

---

## 4. Worker Stalls & Lease Recovery (V14, V16)

- The worker acquires jobs with exclusive leases (`leaseUntil`).
- Active workers renew their leases via heartbeat every 30 seconds.
- If a worker dies ungracefully (`SIGKILL`), its lease expires after 60 seconds. A running peer worker automatically reclaims the job.
- Before generating comments or commits, the worker queries GitHub for the latest PR HEAD SHA. If the PR advanced (`SUPERSEDED`), the run is aborted without posting stale docs (V16).

---

## 5. AI Data Policy & Privacy

- **Redacted Files**: `.env*`, `.pem`, `.key`, `id_rsa`, certificates, tokens, lockfiles, and binary files are automatically stripped from diffs before reaching the Gemini API.
- **Diff Truncation**: Diffs are limited to 35,000 characters. When truncated, an explicit notice is added to the review comment.
- **Structured Schema**: Analysis output must strictly adhere to validated Zod schemas. Model hallucinations outside the schema are caught and classified as `INVALID_OUTPUT`.
- **Zero Writing without Approval**: AI suggestions are created as `DocProposal` with status `PENDING_APPROVAL`. No automated commits occur without authenticated human review.
